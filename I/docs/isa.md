# VH16I Base Integer ISA Specification

**Status:** Draft v0.1  
**Architecture:** VH16  
**Extension:** I — Base Integer  
**Instruction width:** 32 bits  
**Register width:** 16 bits  
**Data bus:** 16 bits  
**Address bus:** 16 bits  
**Byte order:** Little-endian  

> VH16I is a custom RISC architecture inspired by RISC-V design principles.  
> It is **not binary-compatible with RISC-V**.

---

## 1. Architectural overview

VH16I is a 16-bit load/store architecture intended to be simple enough for a discrete-logic / DTL implementation while remaining convenient to program.

The base architecture has:

- 16 general-purpose registers, `x0` through `x15`
- 16-bit integer registers
- 16-bit ALU
- 16-bit data bus
- 16-bit address bus
- 32-bit fixed-width instructions
- byte-addressed memory
- little-endian memory ordering
- no architectural condition-code / flags register
- PC-relative branches and jumps
- a microarchitectural 16-bit MAR

### 1.1 Address space

The address bus is 16 bits wide.

Therefore the architectural address space is:

```text
0x0000 .. 0xFFFF
```

or 64 KiB of byte-addressed memory.

All arithmetic on addresses wraps modulo `2^16`.

---

## 2. Registers

VH16I contains 16 architectural integer registers.

| Register | Meaning |
|---|---|
| `x0` | hard-wired zero |
| `x1`–`x15` | general-purpose 16-bit registers |

### 2.1 x0

`x0` always reads as:

```text
0x0000
```

Writes to `x0` are discarded.

This allows several operations to be represented without dedicated opcodes.

Examples:

```asm
add   x3, x4, x0        # move x4 -> x3
addi  x5, x0, 123       # load immediate
sub   x6, x0, x6        # negate
```

### 2.2 Register aliases

No ABI register aliases are architecturally defined yet.

A future ABI may define conventions such as:

```text
x1 = ra
x2 = sp
```

but these are not part of the base ISA.

---

## 3. Program Counter

`PC` is a 16-bit register containing the byte address of the current instruction.

All instructions are 32 bits = 4 bytes.

Normal sequential execution performs:

```text
PC <- PC + 4
```

Instruction addresses must be 4-byte aligned:

```text
PC[1:0] = 00
```

Branch and jump targets are also required to be 4-byte aligned.

---

## 4. MAR

MAR means **Memory Address Register**.

The MAR is a 16-bit **microarchitectural** register. It is not directly visible to software and has no register number.

Its purpose is to hold a stable memory address during instruction fetches and load/store operations.

Typical use:

```text
effective_address -> MAR -> address bus
```

For example:

```asm
l16 x3, 8(x4)
```

may internally execute approximately:

```text
MAR <- x4 + 8
x3  <- MEM16[MAR]
```

The exact number of clock cycles is implementation-specific.

---

## 5. Memory model

VH16I uses a unified byte-addressed memory space.

The implementation has:

```text
Address bus : 16 bits
Data bus    : 16 bits
```

### 5.1 Little-endian ordering

For a 16-bit value:

```text
0xABCD
```

stored at address `0x1000`:

```text
Address  Value
0x1000   0xCD
0x1001   0xAB
```

Therefore:

```text
MEM16[0x1000] = 0xABCD
```

### 5.2 16-bit alignment

Base VH16I requires 16-bit memory operations to use an even address:

```text
address[0] = 0
```

Misaligned `l16` / `s16` accesses are currently reserved and must not be generated by software.

A future implementation may add hardware support for unaligned accesses.

### 5.3 Instruction fetch

Because an instruction is 32 bits while the data bus is 16 bits, an instruction requires two 16-bit memory transfers.

For an instruction at `PC`:

```text
IR[15:0]  <- MEM16[PC]
IR[31:16] <- MEM16[PC + 2]
```

Then:

```text
PC <- PC + 4
```

Because memory is little-endian, the lower-addressed halfword contains instruction bits `[15:0]`.

---

# 6. Instruction encoding

All instructions are exactly 32 bits.

Bit numbering:

```text
31                              0
+--------------------------------+
|         32-bit instruction     |
+--------------------------------+
```

The most significant 8 bits are always the opcode.

```text
31          24 23               0
+-------------+-------------------+
|   OPCODE    |      PAYLOAD      |
+-------------+-------------------+
     8 bits          24 bits
```

Opcode ranges are grouped by instruction class:

| Opcode range | Class |
|---|---|
| `0x00`–`0x0F` | R-type register ALU |
| `0x10`–`0x1F` | I-type immediate ALU |
| `0x20`–`0x2F` | Memory |
| `0x30`–`0x3F` | Branch |
| `0x40`–`0x4F` | Jump |
| `0x50`–`0xEF` | Reserved |
| `0xF0`–`0xFF` | System / reserved |

This grouping is intended to simplify a hardwired decoder.

---

## 7. R-type

R-type instructions operate on registers.

```text
31       24 23   20 19   16 15   12 11              0
+----------+-------+-------+-------+-------------------+
|  OPCODE  |  RD   |  RS1  |  RS2  |     RESERVED      |
+----------+-------+-------+-------+-------------------+
    8          4       4       4            12
```

`RESERVED` must be zero.

General semantic form:

```text
rd <- operation(rs1, rs2)
```

Writes to `x0` are discarded.

### 7.1 R-type opcode table

| Opcode | Mnemonic | Operation |
|---:|---|---|
| `0x00` | `ADD` | `rd = rs1 + rs2` |
| `0x01` | `SUB` | `rd = rs1 - rs2` |
| `0x02` | `AND` | `rd = rs1 & rs2` |
| `0x03` | `OR` | `rd = rs1 \| rs2` |
| `0x04` | `XOR` | `rd = rs1 ^ rs2` |
| `0x05` | `SLL` | logical left shift |
| `0x06` | `SRL` | logical right shift |
| `0x07` | `SRA` | arithmetic right shift |
| `0x08` | `SLT` | signed less-than |
| `0x09` | `SLTU` | unsigned less-than |
| `0x0A`–`0x0F` | — | reserved |

### 7.2 Arithmetic behavior

Arithmetic wraps modulo `2^16`.

Example:

```text
0xFFFF + 0x0001 = 0x0000
```

No arithmetic overflow exception is generated.

### 7.3 Shift amount

Register shift instructions use:

```text
shift_amount = rs2[3:0]
```

Therefore the shift amount is 0–15.

### 7.4 SLT / SLTU

`SLT` performs a signed 16-bit comparison:

```text
rd = (signed(rs1) < signed(rs2)) ? 0x0001 : 0x0000
```

`SLTU` performs an unsigned comparison:

```text
rd = (unsigned(rs1) < unsigned(rs2)) ? 0x0001 : 0x0000
```

---

## 8. I-type

I-type instructions use one source register and one 16-bit immediate.

```text
31       24 23   20 19   16 15                    0
+----------+-------+-------+-------------------------+
|  OPCODE  |  RD   |  RS1  |         IMM16          |
+----------+-------+-------+-------------------------+
    8          4       4               16
```

General form:

```text
rd <- operation(rs1, imm16)
```

### 8.1 I-type opcode table

| Opcode | Mnemonic | Operation |
|---:|---|---|
| `0x10` | `ADDI` | `rd = rs1 + imm16` |
| `0x11` | `ANDI` | `rd = rs1 & imm16` |
| `0x12` | `ORI` | `rd = rs1 \| imm16` |
| `0x13` | `XORI` | `rd = rs1 ^ imm16` |
| `0x14` | `SLLI` | logical left shift immediate |
| `0x15` | `SRLI` | logical right shift immediate |
| `0x16` | `SRAI` | arithmetic right shift immediate |
| `0x17`–`0x1F` | — | reserved |

### 8.2 ADDI immediate

For `ADDI`, `imm16` is interpreted as a 16-bit two's-complement integer.

Because the register width is also 16 bits, addition is simply performed modulo `2^16`.

### 8.3 Logical immediates

For:

```text
ANDI
ORI
XORI
```

`imm16` is treated as a raw 16-bit bit mask.

### 8.4 Immediate shifts

For:

```text
SLLI
SRLI
SRAI
```

the shift amount is:

```text
imm16[3:0]
```

The assembler should require:

```text
imm16[15:4] = 0
```

---

# 9. Memory type

Memory instructions use a base register plus a signed 16-bit offset.

```text
31       24 23   20 19   16 15                    0
+----------+-------+-------+-------------------------+
|  OPCODE  |  REG  | BASE  |        OFFSET16         |
+----------+-------+-------+-------------------------+
    8          4       4               16
```

Effective address:

```text
EA = BASE + OFFSET16
```

with 16-bit wraparound.

Assembly syntax:

```asm
l16  rd, offset(base)
s16  rs, offset(base)
```

### 9.1 Memory opcode table

| Opcode | Mnemonic | Operation |
|---:|---|---|
| `0x20` | `L16` | load 16-bit value |
| `0x21` | `S16` | store 16-bit value |
| `0x22` | `L8` | load signed 8-bit value |
| `0x23` | `L8U` | load unsigned 8-bit value |
| `0x24` | `S8` | store low 8 bits |
| `0x25`–`0x2F` | — | reserved |

### 9.2 L16

```asm
l16 rd, offset(base)
```

Operation:

```text
EA = base + signed(offset16)
rd = MEM16[EA]
```

`EA` must be even.

### 9.3 S16

```asm
s16 rs, offset(base)
```

Operation:

```text
EA = base + signed(offset16)
MEM16[EA] = rs
```

`EA` must be even.

### 9.4 L8

```asm
l8 rd, offset(base)
```

Loads one byte and sign-extends it:

```text
rd = sign_extend_8_to_16(MEM8[EA])
```

Example:

```text
MEM8[EA] = 0x80
rd       = 0xFF80
```

### 9.5 L8U

```asm
l8u rd, offset(base)
```

Loads one byte and zero-extends it:

```text
rd = zero_extend_8_to_16(MEM8[EA])
```

Example:

```text
MEM8[EA] = 0x80
rd       = 0x0080
```

### 9.6 S8

```asm
s8 rs, offset(base)
```

Stores:

```text
rs[7:0]
```

to the addressed byte.

# 10. B-type

Branches compare two registers.

```text
31       24 23   20 19   16 15                    0
+----------+-------+-------+-------------------------+
|  OPCODE  |  RS1  |  RS2  |         DISP16          |
+----------+-------+-------+-------------------------+
    8          4       4               16
```

VH16I has no architectural condition-code register.

Branches perform comparisons directly.

### 10.1 Branch target

`DISP16` is a signed displacement measured in **instructions**, not bytes.

If the branch is taken:

```text
target = (PC + 4) + (sign_extend(DISP16) << 2)
```

All arithmetic wraps to 16 bits.

If the branch is not taken:

```text
PC <- PC + 4
```

### 10.2 Branch opcode table

| Opcode | Mnemonic | Condition |
|---:|---|---|
| `0x30` | `BEQ` | `rs1 == rs2` |
| `0x31` | `BNE` | `rs1 != rs2` |
| `0x32` | `BLT` | signed `rs1 < rs2` |
| `0x33` | `BGE` | signed `rs1 >= rs2` |
| `0x34` | `BLTU` | unsigned `rs1 < rs2` |
| `0x35` | `BGEU` | unsigned `rs1 >= rs2` |
| `0x36`–`0x3F` | — | reserved |

Example:

```asm
beq x1, x2, loop
```

# 11. J-type

## 11.1 JAL

`JAL` performs a PC-relative jump while optionally saving the return address.

Encoding:

```text
31       24 23   20 19   16 15                    0
+----------+-------+-------+-------------------------+
|  OPCODE  |  RD   | RSV=0 |         DISP16          |
+----------+-------+-------+-------------------------+
    8          4       4               16
```

Opcode:

```text
0x40 = JAL
```

Operation:

```text
rd     <- PC + 4
PC     <- (PC + 4) + (sign_extend(DISP16) << 2)
```

If:

```text
rd = x0
```

the return address is discarded, producing an unconditional jump.

---

## 11.2 JALR

`JALR` uses the I-type encoding:

```text
31       24 23   20 19   16 15                    0
+----------+-------+-------+-------------------------+
|  OPCODE  |  RD   |  RS1  |         IMM16           |
+----------+-------+-------+-------------------------+
```

Opcode:

```text
0x41 = JALR
```

Operation:

```text
tmp <- PC + 4
PC  <- (rs1 + signed(imm16)) & 0xFFFC
rd  <- tmp
```

The low two target bits are cleared so that the destination remains 4-byte aligned.

A common return sequence, if an ABI later assigns `x1` as the return-address register, is:

```asm
jalr x0, x1, 0
```

# 13. Pseudo-instructions

The following are assembler conveniences and do not require additional hardware opcodes.

## NOP

```asm
nop
```

expands to:

```asm
addi x0, x0, 0
```

## MOV

```asm
mov rd, rs
```

expands to:

```asm
add rd, rs, x0
```

## LI

```asm
li rd, imm16
```

expands to:

```asm
addi rd, x0, imm16
```

Because VH16 registers and immediates are both 16 bits wide, no `LUI` instruction is required in the base ISA.

## NOT

```asm
not rd, rs
```

expands to:

```asm
xori rd, rs, 0xFFFF
```

## NEG

```asm
neg rd, rs
```

expands to:

```asm
sub rd, x0, rs
```

## J

```asm
j label
```

expands to:

```asm
jal x0, label
```

## JR

```asm
jr rs
```

expands to:

```asm
jalr x0, rs, 0
```

# 15. Design rationale

VH16I intentionally keeps several RISC-V-like properties:

- fixed-width instructions
- load/store architecture
- `x0` hard-wired to zero
- register-register ALU operations
- immediate ALU operations
- PC-relative branches
- `JAL` / `JALR`
- no architectural condition-code flags
- pseudo-instructions built from simpler real instructions

The architecture differs from RISC-V where doing so simplifies a 16-bit discrete-logic implementation.

Notable differences include:

- 16-bit registers
- 16 registers instead of 32
- 16-bit address space
- 32-bit instructions with a simple 8-bit opcode field
- full 16-bit immediate in I-type instructions
- 16-bit external data bus
- a design intended for a multi-cycle hardwired controller

---

# 16. Initial implementation recommendation

A first hardware implementation should support, in this order:

1. `ADD`, `SUB`
2. `AND`, `OR`, `XOR`
3. `ADDI`, `ANDI`, `ORI`, `XORI`
4. `L16`, `S16`
5. `BEQ`, `BNE`
6. `JAL`, `JALR`
7. shifts
8. signed/unsigned comparison instructions
9. byte loads/stores
10. remaining conditional branches

This allows the datapath and hardwired controller to be brought up incrementally.

---

# 17. Future extensions

The following are deliberately excluded from VH16I v0.1 and may become separate extensions:

- multiply / divide
- interrupts
- exceptions
- privileged mode
- CSR registers
- atomic operations
- compressed instructions
- floating point
- bit-manipulation instructions
- hardware debug instructions
- memory protection
